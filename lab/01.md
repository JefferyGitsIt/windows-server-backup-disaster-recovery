# 1. Understanding Backup Types
Different backup methods provide different levels of data protection and recovery capabilities.

| Backup Type | Description | Use Case |
| :--- | :--- | :--- |
| Full Backup | Protects all selected data | Complete file or server backup |
| Incremental Backup | Protects data changed since a previous backup | Efficient recurring backups |
| System State Backup | Protects critical Windows operating system components | Active Directory recovery |
| Bare-Metal Recovery Backup | Provides the components needed to recover a server installation | Recovery after server failure |
| File-Level Backup | Protects selected files and folders | Recovery of deleted or modified files |

Understanding these backup methods helps me determine the appropriate recovery strategy for different systems.

## 3. Backup and Recovery Strategy
Developed the following initial backup plan:

| Component | Backup Strategy | Planned Recovery Test |
| :--- | :--- | :--- |
| FILE01 departmental files | Daily file backup | Restore an accidentally deleted test file |
| DC01 Active Directory | System state backup | Recover a test Active Directory object using an appropriate recovery procedure |

FILE01 was selected as the first backup target because file-level recovery provides a relatively safe introduction to backup operations.
More advanced Active Directory and server recovery operations will be performed after the basic backup process has been verified.

## 4. Recovery Objectives
2 Important concepts in disaster recovery planning are:
**Recovery Point Objective (RPO)**: The maximum acceptable amount of data loss measured in time.
**Recovery Time Objective (RTO)**: The maximum acceptable amount of time required to restore a service after an outage.

For this educational homelab, the following targets are proposed:

| Service | Planning RPO | Planning RTO |
| :--- | :--- | :--- |
| FILE01 departmental data | 24 hours | 4 hours |
| DC01 directory services | 24 hours | 4 hours |

These are planning targets, not measured recovery guarantees. They will required validation through actual recovery tests.

## 5. Backup Storage Planning
Backup storage will use additional virtual hard disks attached to the existing Hyper-V virtual machines.

For FILE01, the planned storage configuration is:
| Disk | Purpose | Capacity |
| :--- | :--- | :--- |
| Operating system disk | Windows Server 2025 | 80 GB |
| Departmental data disk | Business files | 50 GB |
| Backup disk | Windows Server Backup destination | 100 GB |

The backup disk will be dedicated to storing recovery points created by Windows Server backup.

## Storage Limitations
Although the backup disk is logically separate from the source data disk, both virtual disks reside on the same physical Hyper-V host.

This configuration supports learning backup and recovery procedures but does not provide protection against physical host or storage failure.
A production strategy should include independent backup storage, offline or offsite copies, and periodic recovery testing.

## 6. Backup Verification Strategy
A completed backup job does not automatically guarantee recoverability.
The following verification activities are planned:
- Review Windows Server Backup job status.
- Confirm backup completion without reported errors.
- Identify available backup recovery points.
- Restore a selected test file.
- Validate the contents of the restored file.
- Document recovery results and any limitations.

The success of a recovery test will provide stronger evidence of recoverability than backup status alone.

## 7. Security Considerations
Backup systems may contain sensitive organizational information and should be protected accordingly.

Important practices include restricting access to backup storage, protecting administrative credentials, monitoring backup failures, and maintaining independent backup copies.
Recovery operations involving Active Directory should be performed using supported recovery procedures and isolated test environments to minimize the risk of disrupting production services.

## 8. Lessons Learned
This planning exercise reinforced several important concepts:
- Different systems require different backups and recovery methods.
- File backups and system state backups serve different purposes.
- RPO and RTO help define recovery expectations.
- Backup storage should be protected independently from primary data whenever possible.
- A successful backup operation must be followed by recovery testing.
- Disaster recovery planning should prioritize critical services and minimize operational disruption.
